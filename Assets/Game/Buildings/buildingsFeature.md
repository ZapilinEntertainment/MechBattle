# Building feature
Строения - разрушаемые декорации с набором функций.

## Создание
 1) Подготовьте gameobject с моделью. Добавьте на корневой объект компонент BuildingView (или производный, например FactionBuildingView если есть части, которые нужно красить в цвета фракции).
 2) Заполните поля в компоненте
  - Health - очки здоровья
  - Colliders - активные коллайдеры здания. Обратите внимание - декоративные части лучше указать как отдельные buildingViews, чтобы их повреждение не влияло на общее хп
  - DestroyEffectKey - эффект разрушения
  - Function flags - указанный функционал будет добавлен при сборке (см. в разделе Инициализация)
  - Block config - параметры блокировки проходимости. 
	> IsValid - Если здание не блокирует проход и не должно считаться как цель атаки, снимите галочку, иначе установите её.
	> Mode - вариант зоны блокировки (круг, прямоугольник). Редактор отрисует gizmo занятой зоны.
	> ExtentA, ExtentB - размеры. Если вариант предполагает только один размер (радиус круга например), то вводите только первое значение
	> Flags - обозначает, каким именно типам юнитов здание блокирует проход (НЕ РЕАЛИЗОВАНО)
 3) Расставьте объекты по карте
 
## Инициализация
 1) При подготовке карты SceneBuildingsInitializer подхватит все объекты BuildingView и передаст их BuildingsFactory на доработку 
 2) BuildingsFactory создает Morpeh-сущность в World и связывает ее с BuildingView. Также фабрика проходится по флагам:
  - Spawner: если на объекте есть UnitsSpawnerMono, то ему добавится функционал спаунера юнитов.
  
## Building features
 Зарегистрируйте feature applier как IBuildingFeatureApplier чтобы внедрять функционал в сборку (точнее конверсию из view в entity) здания. Нужно задать триггер-флаг, чтобы фабрика задействовала апплаер.
  
## Блокировка пути
 - Если у BuildingView есть валидная блокер-дата, то фабрика добавит её сущности BlockZoneConfigComponent. Это будет иметь 2 последствия:
 1) Юниты будут обходить здание используя AvoidanceSystem и учитывая OccupationFlags
 2) Здание будет учитываться как доступная цель, если на нем есть PlayerAffiliationComponent
 3) (НЕ РЕАЛИЗОВАНО) вероятно, размещение здания должно вызывать пересчет флоу-карт и доступных путей
 
 - При разрушении блокировка путей снимается
 - Одну и ту же клетку могут блокировать 2 разных здания. При наложении блокировок их флаги блокировок складываются (если допустим здание А блокирует проход маленьким юнитам, а здание Б - авиации, то клетка будет заблокирована для обоих). При удалении одной из блокирующих сущностей клетка пересчитается.
