# Mono Views
 Unity Views существуют как отдельные объекты в игровом мире, их позиции синхронизуются с компонентами PositionComponent \ RotationComponent через TransformAccess (TransformAccessManager / TransformsSyncSystem). Для мгновенного создания views и отсутствия статтеров установлена следующая схема:
 а) для объектов, которые создаются через код:
 1) сначала создается transform-пустышка (ViewContainer). Это poolable объект, которые принимает внутрь себя настоящий view сущности. Во ViewKeyComponent записывается идентификатор ассета, который указан в конфиге сущности
 2) Для загрузки нужной модели на сущность вешается ViewLoadRequestTag
 3) ViewRequestsHandleSystem создает и проверяет ViewProviders - объекты, которые хранят данные о состоянии загрузки и сами загруженные префабы. Как только провайдер готов предоставить ассет, интанциируем настоящий view и присваиваем его view container-у.
 4) в кадр может вызваться только ограниченное количество сущностей (GameConstants.MAX_VIEW_INSTANTIATIONS_PER_FRAME)
 
 # View Containers
 Все view containers регистрируются по ключу в IViewContainersManager, ключ добавляется компонентом ViewContainerComponent на сущность.
 Также возможно регистрировать одноразовые (не-poolable) view как самостоятельные view containers (для унификации работы с view). Логика диспоза определяется в самом IViewContainer, поэтому мы можем диспозить все объекты в менеджере одинаково.
 Каждый новое создание или регистрация контейнера увеличивает счетчик id - даже многократно вызванный контейнер из пула будет возвращаться с разными id. 
 
 # ViewProviders
 ViewProvidersFactory выдает провайдеров - объекты, которые предоставляют по возможности загружаемый addressable ассет. Если загружаемая view поддерживает пуллинг, то фабрика создаст ViewPool, иначе - обычный ViewProvider. Пока идет загрузка, фабрика выдает провайдер-заглушку, у которого всегда IsReady == false
 
 # View Parts
 Сложные объекты из нескольких частей могут собираться как несколько сущностей, но при этом с одним префабом модели. Для этого вью модели должна реализовывать IComplexView и отдавать ссылки на куски по ключам. Как только базовая модель загрузится, ViewPartAssignSystem раздаст ее части под контроль каждой из назначенных сущностей.
