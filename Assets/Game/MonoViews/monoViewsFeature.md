#Mono Views
 Views сущностей сначала создаются как viewContainer, а затем на него добавляется настоящая view объекта (может задержаться если модель еще грузится из ассетов или если лимит инстансов в кадр или объектов на карте переполнен). При диспозе view container убирается обратно в пул, а view диспозится. Каждый новый вызов контейнера увеличивает счетчик id - даже многократно вызванный контейнер из пула будет возвращаться с разными id. 
 Управление контейнерами идет через IViewContainersManager, поскольку сущности хранят не ссылку на сам контейнер, а ключ. Операции над контейнерами выполняются по ключу, что позволяет смешивать poolable и не-poolable контейнеры - в списке они хранятся по интерфейсу IViewContainer и сами определяют логику по диспозу.
 
 #ViewProviderFactory 
 Фабрика выдает провайдеров - объекты, которые предоставляют по возможности загружаемый addressable ассет. Если загружаемая view поддерживает пуллинг, то фабрика создаст ViewPool, иначе - обычный ViewProvider. Пока идет загрузка, фабрика выдает провадйер-заглушку, у которого всегда IsReady == false
