# Состояния сущностей \ Entity states

## Применение
Сущности могут управляться стейт-машиной. Система обновляет каждую сущность, используя логику в стейт-объекте.

## Когда использовать
- Поведение сущности можно задать четкой логикой
- Количество состояний конечно и не предполагает смешивания
- Сложный объект с большим количеством логических параметров и возможностями (двигается, стреляет, использует способности)

## Когда НЕ использовать
- Логика состояний очень простая и может быть реализована в рамках одной-двух систем

## Внутреннее устройство
- Модуль фич, реализующие IEntityStateInstaller биндят и выдают на регистрацию объекты стейтов
- Каждый стейт кодируется двумя ключами (enum) - behaviour и state
- Ключ state позволяет переключать стейты на юните, ничего не зная о конкретной реализации
- Ключ behaviour позволяет менять поведение сущности уже в следующий фрейм
- Система обновления стейтов применяет логику согласно этим двум ключам, получая объект стейта из StateBehavioursDictionary
- Ключи хранятся на сущности в компонентах StateComponent и BehaviourKeyComponent
- Систем обновления стейтов можно задать несколько, так как базовая система обновления - generic по типу IStateMachinePriorityTag. Сейчас есть 2 типа приоритет - HighPriorityStateMachineTag (выполняется первой) и RegularPriorityStateMachineTag (выполняется второй). Это нужно, например, чтобы поведение взводов (HighPriority) не перебивалось личным поведением юнитов в нем (RegularPriority) 


## Реализация
- Каждый стейт наследуется от StateHandler. У него три метода - Enter, Exit и Update. Update должен вернуть ключ следующего стейта (допустим стейт idle возвращает ключ idle если ничего не меняет, но если вернет ключ move, то следующим стейтом соответственно будет движение)
- Переключение осуществляется следующим образом - в компоненте StateComponent содержатся CurrentState - текущий и NextState  - следующий. в некст можно писать вручную и тогда стейт переключится сам, иначе его определит следующий update стейта.
- Для создания компонентов при сборке сущности используйте StatesApplier


## Регистрация зависимостей идет через EntityStateFeatureModule, сами стейты регистрируются в инсталлерах своих фич

## Дополнительно
- используйте FeatureStateInstallerBase (в том числе как внутренний класс фича-модуля) чтобы быстро добавить нужные стейты. Пример - SquadStatesInstaller внутри SquadSubfeatureInstaller
- объекты стейтов можно использовать одновременно в разных стейтах, просто отметьте isAlias в конструкторе FeatureStateInstallerBase и добавляйте инсталлер как обычно
