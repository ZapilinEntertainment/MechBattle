# Запросы \ Requests

## Применение
Часть запросов создается отдельными сущностями, чтобы реализовывать более комплексную логику обработку запросов

## Когда использовать
- Запрос создается вне ecs-мира (скрипты-утилиты) и может нарушить логику исполнения систем
- Запрос может нести дополнительную информацию
- Запрос может жить несколько циклов
- Необходимо получить результат выполнения

## Когда НЕ использовать
- Запрос простой и нам не нужно получать результат
- Запросов этого типа очень много и они живут ровно 1 цикл,  после чего мы можем очистить список полностью

## Внутреннее устройство
- Запрос создается на фабрике-наследнике RequestFactoryBase
- Компонент запроса реализует IRequestComponent
- Запрос обрабатывается системой-наследником RequestHandleSystemBase. Запрос может быть принят или отклонен. Отклоненные запросы по умолчанию стираются, но могут и быть отложены (пример: UnitsCreationSystem)
- Выполненный запрос получает тег CompletedRequestTag
- система CompletedRequestsClearSystem стирает все выполненные запросы

## Получение результата запроса
- Чтобы записать результат выполнения в запрос необходимо:
1) при его создании повесить на него компонент CreationRequestResultComponent (или воспользоваться CreationRequestsHandler чтобы асинхронно ожидать результат)
2) в системе-обработчике записать туда сущность-результат
- CompletedRequestsClearSystem запишет результат в CreationResultsList
- при получении результата вручную (не через CreationRequestsHandler) нужно стереть результат из CreationResultsList

## Регистрация зависимостей идет через MorpehFeatureBase

## Примеры
- MechInstanceSystem создает мех по запросам и записывает результат
- UnitsCreationSystem создает юнитов по запросам по мере возможности (проверяя доступность ячеек карты) и не записывает результат
- системы нанесения урона не пользуются запросами-сущностями а пишут в отдельный объект ReceivedDamageList и читают из него, очищая каждый кадр
